# Project roadmap

This is a planning document, not a promise that every item is scheduled.

## Public repository preparation
- Complete the software licence decision for original code.
- Resolve third-party asset redistribution questions.
- Add screenshots from a tested current build.
- Verify clean Windows installation and first-run experience.
- Publish issue templates and contribution guidance.

## Community launch
- Publish the repository from the maintainer's personal GitHub account.
- Write a technical development article explaining the architecture and lessons learned.
- Share a short demo in relevant communities only where project posts are allowed.
- Ask for concrete feedback: installation, performance, accessibility, memory, character animation, and provider integration.
- Avoid posting identical promotional messages repeatedly. Participate in community discussions and follow each community's rules.

## Maintenance
- Triage reproducible bugs.
- Label beginner-friendly issues.
- Review pull requests and dependency updates.
- Publish release notes with known limitations.
- Track installation success, contributors, and useful feedback rather than focusing only on star count.

## Funding
Once the project is public and the maintainer has an active funding profile, add `.github/FUNDING.yml` with the correct personal GitHub Sponsors username or other supported funding link. Explain clearly that sponsorship supports maintenance and development; it does not purchase creator endorsement or special access.
